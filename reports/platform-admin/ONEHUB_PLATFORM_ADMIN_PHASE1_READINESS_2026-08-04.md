## Current code state

### Canonical authority gate

`apps/web/src/lib/rbac.ts` defines `GUARDED_MVP_PLATFORM_ADMIN_AUTHORITY = "PLATFORM_ADMIN"` and implements guarded MVP Platform Admin as:

- user must exist;
- user must satisfy `isAdmin(user)`;
- user ID must be included in comma-separated `process.env.GUARDED_MVP_PLATFORM_ADMIN_USER_IDS`.

This means the env value must be the OneHub `User.id`, not an email address.

### Authority lookup

`getGuardedMvpAuthorityForUserId(userId)` loads `{ id, email, name, role }` from Prisma and returns the user only if `isPlatformAdminForGuardedMvp(user)` passes. This keeps the final authority check centralized on current DB role plus the env allowlist.

### Surfaces depending on the guarded authority

Observed call paths include:

- Break-glass impersonation: `apps/web/src/app/api/admin/impersonate/route.ts`
  - Uses the real session user ID, calls `getGuardedMvpAuthorityForUserId(realUserId)`, requires `reason` and `incidentTicketId`, writes audit, and returns a signed short-lived session update.
- Admin verification server actions: `apps/web/src/app/(app)/admin/verification/actions.ts`
  - Requires current user to be app `ADMIN`, pass dashboard access, and pass `assertPlatformAdminForGuardedMvp(user)` before refund, dispute, or holdback decisions.
- Admin overrides: `apps/web/src/lib/admin-override.ts`
  - Requires guarded authority before recording admin override rows.
- Payment release: `apps/web/src/app/api/payments/release-milestone/route.ts`
  - Uses `canReleaseMilestonePayment(user, event)`, which delegates to `isPlatformAdminForGuardedMvp`.
- Holdbacks: `apps/web/src/lib/holdback.ts`
  - Uses `isPlatformAdminForGuardedMvp` for holdback management.
- Refund and dispute reviews:
  - `apps/web/src/lib/refund-request.ts`
  - `apps/web/src/lib/dispute-case.ts`
